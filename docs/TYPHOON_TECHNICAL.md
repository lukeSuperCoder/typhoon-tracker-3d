# 三维台风路径动画 Web 项目——初步需求与技术方案 V0.1

## 一、项目定位

建设一个基于 Mapbox GL JS 的三维台风路径动画 Web 应用，以全球球体视角展示台风的历史路径、预测路径、强度变化和风圈范围。

项目优先实现具有展示效果的单台风播放功能，同时为后续接入实时数据、多台风对比、风场粒子和卫星云图预留扩展能力。

### 核心体验

用户进入页面后，可以：

1. 从三维地球视角查看台风所在区域。
2. 选择一个历史或当前台风。
3. 播放台风从生成到消亡的完整过程。
4. 查看台风模型沿真实路径移动。
5. 查看路径节点、强度颜色和风圈随时间变化。
6. 暂停、拖动时间轴或调整播放速度。
7. 在自由观察和自动跟随之间切换。

---

## 二、目标用户

第一阶段主要面向：

- 气象科普与展示用户
- 地图可视化作品访问者
- 应急指挥或数字孪生演示场景
- 台风历史数据研究人员
- 项目汇报和大屏展示用户

第一版定位为可视化播放平台，不承担专业气象预报和灾害决策责任。

## 三、第一阶段需求范围

### 3.1 三维地球

使用 Mapbox GL JS Globe 投影，提供：

- 全球三维球体
- 星空背景
- 大气层与地平线渐变
- 海洋、陆地、国界和城市标注
- 鼠标旋转、缩放和倾斜
- 自动定位到台风活动区域
- 平滑镜头飞行
- 卫星、深色和标准地图主题切换

建议默认采用适合气象展示的深色卫星主题，降低底图对台风路径的视觉干扰。

### 3.2 台风选择

提供台风列表或选择器，展示：

- 中文名
- 英文名
- 国际编号
- 年份
- 当前或最终等级
- 起止时间
- 活跃/历史状态

第一版可以内置3～5个历史台风作为演示数据。

### 3.3 台风路径

路径分为两部分：

- 历史路径：实线
- 预测路径：虚线或半透明线

每个路径节点包含：

- 时间
- 经度、纬度
- 中心气压
- 最大风速
- 台风等级
- 移动方向
- 移动速度
- 七级、十级、十二级风圈半径

路径按照台风等级着色：

| 等级 | 建议颜色 |
|---|---|
| 热带低压 | 蓝色 |
| 热带风暴 | 青色 |
| 强热带风暴 | 黄色 |
| 台风 | 橙色 |
| 强台风 | 红色 |
| 超强台风 | 紫红色 |

等级颜色应当统一配置，避免写死在不同组件中。

### 3.4 台风动画模型

台风中心使用 GLB/glTF 模型或组合视觉对象表示。

第一版效果包括：

- 模型沿路径平滑移动
- 云团持续旋转
- 模型随台风等级改变尺寸
- 根据移动方向调整整体朝向
- 中心位置显示呼吸光圈
- 台风名称标签跟随移动
- 模型在不同缩放级别下保持可识别

优先使用 Mapbox原生 `model` 图层，以确保 Globe 模式兼容。

如果原生模型无法满足云团内部动画要求，第一版采用“静态云团模型＋整体旋转＋透明光效”的组合方式，不立即引入 Three.js 自定义图层。

### 3.5 风圈

展示以下范围：

- 七级风圈
- 十级风圈
- 十二级风圈

风圈根据东北、东南、西南、西北四个象限的半径生成不规则多边形，并随播放时间更新。

视觉要求：

- 半透明填充
- 不同等级使用不同颜色
- 边界线清晰但不过度突出
- 风圈之间允许叠加
- 可单独控制显示与隐藏
- 更新过程中保持平滑，尽量避免闪烁

### 3.6 播放控制

底部提供统一时间控制台：

- 播放
- 暂停
- 重新播放
- 上一个节点
- 下一个节点
- 时间轴拖动
- 当前时间显示
- 播放进度
- 0.5×、1×、2×、4×倍速
- 自动跟随开关
- 循环播放开关

播放进度以真实时间比例映射，但不直接按照实际时间间隔播放。系统应将数天的台风过程压缩为约30～90秒的动画。

### 3.7 信息面板

右侧信息面板展示当前时间点的：

- 台风名称和编号
- 经纬度
- 台风等级
- 最大风速
- 中心气压
- 移动方向
- 移动速度
- 最近城市或海域
- 数据更新时间

可以增加两个小型趋势图：

- 风速变化曲线
- 中心气压变化曲线

图表当前时刻应与地图播放进度同步。

### 3.8 路径节点交互

用户点击路径节点时：

- 暂停或保持当前播放状态
- 弹出节点详情
- 将播放时间跳转到该节点
- 更新台风模型、风圈和信息面板
- 可选择让镜头飞行到该位置

鼠标悬停时显示简要信息，点击后显示完整信息。

### 3.9 图层控制

第一版提供以下开关：

- 台风模型
- 历史路径
- 预测路径
- 路径节点
- 七级风圈
- 十级风圈
- 十二级风圈
- 城市名称
- 三维地形
- 自动跟随

## 八、核心数据结构

```ts
interface Typhoon {
  id: string
  nameZh: string
  nameEn: string
  code: string
  year: number
  status: 'active' | 'historical'
  startedAt: string
  endedAt?: string
  points: TyphoonPoint[]
  forecast?: ForecastTrack[]
}

interface TyphoonPoint {
  id: string
  time: string
  longitude: number
  latitude: number
  pressure?: number
  maxWindSpeed?: number
  level: TyphoonLevel
  movementDirection?: string
  movementSpeed?: number
  windCircles?: WindCircles
}

interface WindCircles {
  level7?: QuadrantRadius
  level10?: QuadrantRadius
  level12?: QuadrantRadius
}

interface QuadrantRadius {
  northeast: number
  southeast: number
  southwest: number
  northwest: number
}

interface ForecastTrack {
  agency: string
  issuedAt: string
  points: TyphoonPoint[]
}

type TyphoonLevel =
  | 'tropical-depression'
  | 'tropical-storm'
  | 'severe-tropical-storm'
  | 'typhoon'
  | 'severe-typhoon'
  | 'super-typhoon'
```

风圈半径统一使用公里，经纬度使用 WGS84，时间统一使用 ISO 8601。

## 九、动画技术方案

### 9.1 统一播放时钟

建立独立的 `PlaybackEngine`，不直接依赖 Mapbox动画。

核心状态包括：

```ts
interface PlaybackState {
  status: 'idle' | 'playing' | 'paused' | 'ended'
  currentTime: number
  startTime: number
  endTime: number
  progress: number
  speed: 0.5 | 1 | 2 | 4
  following: boolean
  loop: boolean
}
```

所有地图图层、模型、图表和文字面板都订阅同一个当前时间，避免各组件自行计时造成不同步。

### 9.2 位置插值

根据当前播放时间查找相邻的两个台风节点：

```text
节点A ───────── 当前时间 ───────── 节点B
```

使用时间比例计算经纬度、风速和气压。

经度插值需要特别处理跨越180°经线的情况，避免模型绕地球反向移动。较长路径建议使用球面插值，而不是简单线性插值。

### 9.3 模型更新

每一帧执行：

1. 计算台风当前位置。
2. 更新模型 GeoJSON 点坐标。
3. 根据前后位置计算移动方位角。
4. 更新模型旋转角度。
5. 根据强度计算模型缩放。
6. 计算云团自身旋转角度。
7. 更新名称标签。
8. 必要时更新跟随镜头。

地图刷新频率目标为60 FPS；数据和风圈不需要每一帧都重建，可限制在每秒10～20次。

### 9.4 路径更新

历史路径根据当前时间截取：

- 当前时间以前：显示为已走路径
- 当前时间以后：隐藏或弱化
- 预测路径：始终使用单独样式

路径不应每帧追加大量坐标。可以根据播放时间计算当前截取索引，并在变化达到一定阈值时更新 GeoJSON。

### 9.5 风圈过渡

两个时间节点之间的四象限半径分别插值，再使用 Turf.js 或自定义球面算法生成多边形。

为降低运算量：

- 风圈每秒更新10～15次
- 单个象限使用固定数量的采样点
- 缓存已生成的节点风圈
- 只对中间过渡状态实时计算

### 9.6 镜头模式

提供三种镜头模式：

- 自由模式：用户自主操作地图
- 跟随模式：镜头中心跟随台风，但不改变缩放
- 演示模式：系统自动调整中心、缩放、倾角和方位

用户主动拖动地图时，可暂时退出自动跟随，避免镜头与用户争夺控制权。

## 十一、数据方案

### 第一阶段

将演示数据作为静态 JSON 放入项目：

```text
public/data/typhoons/2024-gaemi.json
```

优点：

- 不需要后端
- 可直接部署到 GitHub Pages
- 无数据库成本
- 方便调试和版本管理

### 第二阶段

增加数据服务层：

```text
气象数据源 → 定时采集 → 数据清洗 → 数据库 → API → Web前端
```

后端可选：

- Node.js + NestJS
- Python + FastAPI
- PostgreSQL + PostGIS
- Redis缓存

前端组件不能直接依赖静态文件路径，应统一通过 `TyphoonRepository` 读取数据，以便后续无痛切换到 API。

## 十二、性能目标

第一版建议目标：

- 首屏可交互时间不超过5秒
- 普通桌面设备动画稳定在45～60 FPS
- 地图初始化后台风切换不超过1秒
- 单条台风轨迹支持1,000个节点
- 单页面内存尽量控制在500 MB以内
- GLB模型建议控制在5 MB以内
- 首屏总资源建议控制在15 MB以内

优化措施：

- 压缩 GLB模型
- 按需加载台风数据
- 图表延迟加载
- 避免频繁重建 Mapbox Source和Layer
- 使用 `setData()` 更新已有数据源
- 风圈和路径降低更新频率
- 页面不可见时暂停动画
- 移动端关闭部分光效和三维地形

- 仅保留必要读取权限

## 十四、主要风险与应对

### 14.1 Globe模式的模型能力

Mapbox Globe 不支持传统 `CustomLayerInterface`，因此不能把 Three.js 自定义层作为第一版核心方案。

应对：

- 优先验证 Mapbox原生 `model` 图层
- 台风模型采用整体旋转和缩放
- 复杂内部动画拆分为纹理、光圈和业务图层
- 在开发初期制作模型能力验证原型

### 14.2 台风模型视觉比例

真实尺寸的台风模型在全球视角下可能过小，局部视角下又可能过大。

应对：

- 模型采用视觉比例，不完全使用真实尺寸
- 根据缩放级别动态调整模型大小
- 风圈使用真实公里半径
- 明确区分“台风中心标识”和“真实影响范围”

### 14.3 Mapbox费用

Mapbox GL JS 按地图加载量计费，超过免费额度会产生费用。

应对：

- 设置用量告警
- 一个页面只初始化一个 Map实例
- 避免切换页面时反复销毁和创建地图
- 在项目流量增长后评估费用
- 保留迁移 MapLibre 的数据和业务层边界

### 14.4 国内访问

Mapbox和GitHub Pages在中国大陆的访问速度需要实测。

应对：

- 首版先用于作品展示
- 业务数据和模型尽量使用同一部署平台
- 生产项目评估国内托管和地图合规问题
- 预留替换地图服务的能力

### 14.5 数据准确性

不同气象机构的台风等级和预测数据可能存在差异。

应对：

- 每条预测路径标记数据机构
- 保存数据更新时间
- 区分实况、历史和预测数据
- 页面显示数据来源与免责声明

## 十六、MVP验收标准

第一版满足以下条件即可验收：

1. 页面能够正常显示三维地球。
2. 可以选择并加载至少一条完整台风数据。

4. 历史路径能够随播放进度逐步显示。
5. 能够显示四象限七级和十级风圈。
6. 播放、暂停、拖动和倍速功能正常。
7. 信息面板与播放时间同步。
8. 支持自由视角和自动跟随。
9. 页面刷新或切换台风后无明显资源泄漏。
10. 可以通过公开网址访问。
11. 普通桌面设备播放基本流畅。
12. 页面注明数据来源和非预报用途声明。

## 十七、初步结论

第一版确定采用：

**Vue 3 + TypeScript + Mapbox GL JS 3.x + Turf.js + Pinia + ECharts**

技术实现遵循以下原则：

- Mapbox负责三维地球、底图和地理图层。
- 原生 `model` 图层负责台风模型。
- 独立播放引擎负责统一时间。
- Turf.js负责风圈和空间计算。
- ECharts负责气象趋势图。
- 静态 JSON作为第一阶段数据源。
- GitHub Pages或Cloudflare Pages负责初版发布。
- 业务数据层与地图引擎保持适度解耦，为未来迁移、离线部署和实时数据接入预留空间。
